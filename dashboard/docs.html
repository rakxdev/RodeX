API Documentation v1

One API. Every app uses the same endpoints — only your credentials differ.

Authentication

Send two headers on every request:

X-App-Id:  app_1a2b3c4d5e6f7a8b
X-Api-Key: <your secret key>

Keys are shown once at creation. Rotate from the dashboard if leaked. Suspended or deleting apps get 403.

Conventions

  • All requests and responses are JSON.
  • Responses: { "ok": true, "result": ... } or { "ok": false, "error": { "code", "message" } }.
  • Every row needs a pk; sk is optional and defaults to "~".
  • Rows carry a version — pass expected_version to update/delete safely (conflicts return 409).
  • Add "request_id" to writes for idempotency: retries return the original result, never duplicates.

Write a row

POST /v1/item/put
{ "table": "users", "request_id": "req-123",
  "item": { "pk": "USER#1", "sk": "PROFILE", "name": "Rakesh" } }

Optional "overwrite": true replaces an existing row (resets version). Without it, an existing row returns 409.

Read a row

POST /v1/item/get
{ "table": "users", "pk": "USER#1", "sk": "PROFILE" }

Update a row (version-guarded)

POST /v1/item/update
{ "table": "users", "pk": "USER#1", "sk": "PROFILE",
  "data": { "name": "Rakesh v2" }, "expected_version": 1 }

Delete a row

POST /v1/item/delete
{ "table": "users", "pk": "USER#1", "sk": "PROFILE", "expected_version": 2 }

Query rows

POST /v1/query
{ "table": "users", "pk": "USER#1", "sk_prefix": "MSG#", "limit": 50 }

Returns items, has_more and next_start_key (pass it back as start_key to page). limit max 100.

Tables

POST /v1/table/create   { "name": "sessions" }
GET  /v1/tables

Your tables are isolated automatically: physically stored as app_<app_id>_<name>. No other app can touch them (403).

Limits & errors (must-know)

Item sizeMax 20 KB per row (free-tier write budget — keeps you never-throttled).
Rate limits600 req/min per app · 120 writes/min · 240 reads/min. Over → 429.
RetriesOn 429/502/503, wait retry_after (or 1s) and retry — writes are safe thanks to request_id.
Errors400 bad request · 401 bad key · 403 not your table / app suspended · 404 missing row · 409 version conflict or duplicate · 413 too large · 415 send JSON · 429 rate limit · 502/503 retryable
